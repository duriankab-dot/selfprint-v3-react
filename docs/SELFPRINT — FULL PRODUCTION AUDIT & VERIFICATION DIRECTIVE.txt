3. สถานะที่อนุญาต

ในการรายงานผลครั้งนี้ให้ใช้ เพียง 6 สถานะเท่านั้น

MISSING
PARTIAL
IMPLEMENTED
VERIFIED
PRODUCTION READY
BLOCKED
ความหมาย

MISSING
ยังไม่มี implementation หรือ capability ดังกล่าว

PARTIAL
มี implementation บางส่วน แต่ยังไม่ครบตาม requirement หรือยังมี dependency/gap สำคัญ

IMPLEMENTED
มี implementation จริงใน source code แล้ว แต่ยังไม่มีหลักฐานเพียงพอที่จะยืนยันว่า production behavior ถูกต้องครบถ้วน

VERIFIED
ผ่านการทดสอบ/ตรวจสอบด้วยหลักฐานจริงแล้ว

PRODUCTION READY
ผ่าน production-critical requirements และ verification ที่จำเป็นทั้งหมดแล้ว

BLOCKED
มี dependency หรือ critical issue ที่ทำให้ไม่สามารถถือว่าระบบ/feature พร้อม production ได้

ห้ามใช้ DONE, COMPLETE, READY, SHIPPED, 100%, 68% READY หรือ status อื่นแทน 6 สถานะนี้

4. ต้องแยก “Implementation” กับ “Verification”

ห้ามสรุป:

มีไฟล์ service = ทำงานแล้ว

หรือ:

API มี endpoint = API ใช้งานได้

หรือ:

หน้าเว็บเปิดได้ = Product Flow สมบูรณ์

ต้องแยกอย่างชัดเจน:

CODE EXISTS
        ↓
IMPLEMENTED
        ↓
INTEGRATED
        ↓
RUNTIME TESTED
        ↓
VERIFIED
        ↓
PRODUCTION READY

หากยังไม่มี evidence ให้คงสถานะไว้ที่ IMPLEMENTED หรือ PARTIAL

30. ข้อกำชับสุดท้าย

ไม่ใช่เพื่อทำให้รายงานออกมาว่า "พร้อม"

ดังนั้น:

อย่าพยายามเพิ่มสถานะเพื่อให้ระบบดูดีขึ้น

อย่าถือ implementation เป็น verification

อย่าถือ documentation เป็น evidence

อย่าถือ test file เป็น test result

อย่าถือ UI ที่เปิดได้เป็น functional completion

ให้รายงานตามหลักฐานจริงเท่านั้น

เป้าหมายสุดท้ายคือ:

“รู้ให้แน่ชัดว่า Selfprint พร้อม production ตรงไหน และยังไม่พร้อมตรงไหน โดยไม่ให้มี Blind Spot”
