## ขั้นตอนที่ 1: ฐาน (วันที่ 1-3)

### เป้าหมาย
- ตั้งค่าสถาปัตยกรรมแยกต่างหาก
- สร้างสัญญา TypeScript
- ออกแบบเลเยอร์อแดปเตอร์ API
- ศูนย์การเปลี่ยนแปลงฟังก์ชัน Selfprint

### สิ่งที่ส่งมอบได้
1. **ไฟล์:** `src/lib/types/astrovera.ts`
   - ประเภทอินพุต: `AnalysisRequest`, `PersonProfile`
   - ประเภทเอาท์พุต: `AnalysisResponse`, `PersonalityInsight`
   - ประเภทข้อผิดพลาด: `AnalysisError`

2. **ไฟล์:** `src/lib/astrovera-adapter.ts`
   - ฟังก์ชัน: `buildAnalysisRequest()`, `transformAnalysisResponse()`
   - ตรรกะการแปลงล้วน ไม่มีผลข้างเคียง
   - การทดสอบหน่วยที่ครอบคลุม

3. **การตั้งค่า:** `supabase/functions/intelligence/`
   - Edge Function แม่แบบ
   - อ่าน `ASTROVERA_API_KEY` จากสภาพแวดล้อม
   - เรียก Astrovera Brain Gateway (ลวงตัวไว้ก่อน)

### การทดสอบ
- ✅ อแดปเตอร์แปลง Selfprint ข้อมูลอย่างถูกต้อง
- ✅ อแดปเตอร์แปลงแบบย้อนกลับอย่างถูกต้อง
- ✅ Edge Function template ปรับใช้
- ✅ ไม่มีการเปลี่ยนแปลงที่มองเห็นได้สำหรับผู้ใช้

### การปรับใช้
- ปรับใช้โค้ดอแดปเตอร์ (ศูนย์ผลกระทบ)
- ปรับใช้ Edge Function template (ไม่ใช่ฟังก์ชัน)

---

## ขั้นตอนที่ 2: การรวมจิตวิทยา (วันที่ 4-7)

### เป้าหมาย
- แทนที่ Life Path fallback ด้วยโมดูล Astrovera จิตวิทยา
- นำการโทร Astrovera แรก จาก Selfprint
- UI เดียวกัน การวิเคราะห์ที่หลากหลาย

### สิ่งที่ส่งมอบได้
1. **การเชื่อมต่อ:** บริการฉลาด → โมดูล Astrovera จิตวิทยา
   - อแดปเตอร์: `buildPsychologyRequest(finetuneAnswers, mood)`
   - อแดปเตอร์: `transformPsychologyResponse(astroResponse)`

2. **การนำ Edge Function:** `supabase/functions/intelligence/analyze-psychology.ts`
   - อ่าน: finetuneAnswers, mood, birthDate
   - เรียก: Astrovera Brain Gateway (จิตวิทยา)
   - ส่งกลับ: { decisionStyle, strengths, insights, opportunities }

3. **อัปเดต Frontend:** `src/pages/Onboarding.tsx`
   - เรียก: `/functions/v1/intelligence` แทน `/api/nova`
   - ใช้ตอบสนองแปลง (อินเตอร์เฟส)
   - สำรองไปยัง Life Path หาก Astrovera ลง

### การทดสอบ
- ✅ Edge Function ทำงาน
- ✅ อแดปเตอร์แปลงอย่างถูกต้อง
- ✅ ทำงานสำรอง
- ✅ UI การแสดงผลอย่างถูกต้อง
- ✅ Blueprint แสดงเนื้อหาหลากหลาย

### การปรับใช้
- ปรับใช้ Edge Function
- ปรับใช้การรวมอแดปเตอร์
- ตรวจสอบความหน่วงของ Astrovera

## ขั้นตอนที่ 3: การปรับปรุงตัวเลข (วันที่ 8-9)

### เป้าหมาย
- ปรับปรุง Life Path ที่มีอยู่ ด้วยโมดูล Astrovera
- สร้างระบบการให้คะแนนความเชื่อมั่น
- ไม่มีการเปลี่ยนแปลง UI

### สิ่งที่ส่งมอบได้
1. **ตอบสนองหลายโดเมน:** ปรับ Phase 2 ให้รวมตัวเลข
   - อแดปเตอร์: `buildMultiDomainRequest()` - เรียกทั้ง Psychology + Numerology
   - อแดปเตอร์: `synthesizeMultiDomain()` - รวมด้วยคะแนนความเชื่อมั่น

2. **Edge Function:** ส่วนเสริมให้รวมเลขศาสตร์

### การทดสอบ
- ✅ ตัวเลขโหลด
- ✅ การสังเคราะห์
- ✅ คะแนนความเชื่อมั่น
